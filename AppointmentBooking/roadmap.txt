 Before writing any code
 Build SlotWise: a booking website for one small business (for example, a salon). A customer
 chooses a service and a 30-minute slot. An admin defines the services and weekly opening hours,
 then manages bookings.


    MVP CONTRACT

    One provider. Only one customer can be served at a time. Every service is 30 minutes. Slots are aligned to :00 and

 DATABASE / MODEL MAP


 Design the four MongoDB models

                                                  WORKING HOURS
                USER                                                                              SERVICE
                                                    weekday, open, close
            name, email, role                                                                  name, price, 30 min




                                                    APPOINTMENT

 Relationships to remember
 •    User -> Appointment: one customer can have many appointments; an appointment belongs to exactly one
      customer.
 •    Service -> Appointment: one service can appear in many appointments; keep service references by ObjectId.
 •    WorkingHours -> Slots: your server uses business hours to generate slots; slots are not a MongoDB collection.


 Model conventions
 •    Add timestamps: true to track createdAt and updatedAt.
 •    Use required, enum, min, and meaningful defaults to validate fields.
 •    Store appointment start and end as Date (UTC instants), not strings like "10 AM".
 •    Treat role, status, and blocksSlot as server-owned fields; do not trust client-provided values.


     IMPORTANT TECHNICAL DISTINCTION

     A Mongoose unique option builds a MongoDB index; it is not a normal schema validator. Make sure indexes actually
     exist before you test concurrent bookings.

    import { Schema, model } from 'mongoose';

    const userSchema = new Schema({
      name: { type: String, required: true, trim: true },
      email: {
        type: String, required: true, unique: true,
        lowercase: true, trim: true
      },
      passwordHash: {
        type: String, required: true, select: false
      },
      role: {
        type: String, enum: ['customer', 'admin'],

 DATABASE / MODEL EXAMPLES 3-4


 WorkingHours and Appointment schemas
    models/WorkingHours.js


    import { Schema, model } from 'mongoose';

    const timePattern = /^([01]\d|2[0-3]):[0-5]\d$/;
    const hoursSchema = new Schema({
      weekday: {
         type: Number, required: true, unique: true,
         min: 0, max: 6 // 0 = Sunday, 6 = Saturday
      },
      openTime: { type: String, required: true, match: timePattern },
      closeTime: { type: String, required: true, match: timePattern },
      isClosed: { type: Boolean, default: false }
    }, { timestamps: true });

    export default model('WorkingHours', hoursSchema);



 Validation: The admin API must additionally check that openTime is earlier than closeTime and both fit the 30-minute grid. A
 closed day can still keep default times.


    models/Appointment.js


    import { Schema, model } from 'mongoose';

    const appointmentSchema = new Schema({
      customer: {
         type: Schema.Types.ObjectId, ref: 'User', required: true
      },
      service: {
         type: Schema.Types.ObjectId, ref: 'Service', required: true
      },
      startAt: { type: Date, required: true },
      endAt: { type: Date, required: true },
      status: {
         type: String, enum: ['confirmed', 'cancelled'],
         default: 'confirmed'
      },
      blocksSlot: { type: Boolean, default: true }
    }, { timestamps: true });

    appointmentSchema.index(
       { startAt: 1 },
       { unique: true, partialFilterExpression: { blocksSlot: true } }
    );
    export default model('Appointment', appointmentSchema);



 The index enforces one active reservation per start time. It is correct here because all bookings use the same aligned 30-minute
 slot for one provider.

 Three rules that prevent timezone bugs
 •    Pick one business timezone, such as Asia/Kathmandu, in backend configuration. Never rely on the server
      machine's local timezone.
 •    Generate local opening-hour slots using a timezone-aware library such as Luxon; convert each slot to UTC ISO
      before sending it over the API.
 •    Save startAt / endAt as MongoDB Dates. On the frontend, display the slot using the same business timezone.


     HOW TO READ THE EXAMPLE

     10:00 AM on 10 November 2026 in Kathmandu (UTC+05:45) is 04:15 UTC, so the stored start time is
     2026-11-10T04:15:00.000Z.




 What happens on cancellation?

     Illustrative atomic update


     await Appointment.updateOne(
        { _id: appointmentId, customer: req.user.id,
          status: 'confirmed', startAt: { $gt: new Date() } },
        { $set: { status: 'cancelled', blocksSlot: false } }
     );


 Use the matched/modified count to decide whether cancellation succeeded. This prevents a user cancelling another customer's

 THE HARD PART / SLOTS


 How to generate available times
 You do not store every empty slot in MongoDB. Calculate the day's possible slots from
 WorkingHours, then remove already-confirmed appointments.

 Slot generation algorithm
 01 Read the requested date (YYYY-MM-DD) and convert it to the business timezone.

 02 Find the WorkingHours row for that weekday. If closed, return an empty array.

 03 From opening time to closing time, create consecutive 30-minute intervals.

 04 Skip times in the past. Query active bookings within that day using blocksSlot: true.

 05 Remove booked UTC start times, then send the remaining starts as ISO strings.



    Pseudo-code for GET /api/slots


    const date = req.query.date; // validate YYYY-MM-DD
    const localDay = parseBusinessDate(date, BUSINESS_TIMEZONE);
    const hours = await WorkingHours.findOne({ weekday: localDay.weekday });
    if (!hours || hours.isClosed) return res.json([]);

    const starts = generateHalfHours(localDay, hours); // UTC Dates
    const booked = await Appointment.find({
      startAt: { $gte: dayStartUtc, $lt: nextDayStartUtc },
      blocksSlot: true
    }).select('startAt');

    const taken = new Set(booked.map(a => a.startAt.toISOString()));
    res.json(starts.filter(d => d > new Date() &&
      !taken.has(d.toISOString())).map(d => d.toISOString()));




    DO NOT SKIP THIS DETAIL

    The "free slots" response is only a preview. Before saving a booking, the server must revalidate the chosen slot. The
    unique database index handles concurrent requests at the final step.


 For your single timezone, Luxon can convert a business-local start to a UTC instant with DateTime.fromISO(..., { zone: TZ
 }).toUTC(). Take care to use local weekdays when reading WorkingHours.

 BOOKING VALIDATION / HELPER CODE


 Example: validate one chosen slot
 The booking API uses this helper to reject an invalid time before saving. This version assumes one
 provider, a 30-minute grid, same-day opening hours, and a fixed business timezone.


     utils/slots.js - isOpenSlot() implementation


     import { DateTime } from 'luxon';
     import WorkingHours from '../models/WorkingHours.js';

     const TZ = 'Asia/Kathmandu'; // single business timezone

     export async function isOpenSlot(startAt) {
       if (!(startAt instanceof Date) ||
           Number.isNaN(startAt.getTime()) ||
           startAt <= new Date()) return false;

         const local = DateTime.fromJSDate(startAt, { zone: TZ });
         if (!local.isValid || local.minute % 30 !== 0 ||
             local.second !== 0 || local.millisecond !== 0) {
           return false;
         }

         const weekday = local.weekday % 7; // Luxon: Sunday=7
         const hours = await WorkingHours.findOne({ weekday });
         if (!hours || hours.isClosed) return false;

         const time = local.toFormat('HH:mm');
         const end = local.plus({ minutes: 30 }).toFormat('HH:mm');
         return time >= hours.openTime && end <= hours.closeTime;
     }




 Why each check exists
 •    Future: no booking a time that has already passed.
 •    Alignment: 10:00 and 10:30 are valid; 10:15 is not.
 •    Business timezone: use local weekday/open hours, not UTC weekday.
 •    Availability: this helper checks schedule rules. The unique database index separately blocks slots that someone
      else already reserved.


     WEEK 3 IMPLEMENTATION TIP

     Write unit tests for this helper with a closed day, a valid weekday, 10:15, a past time, and the last allowed slot. Then
     connect it to POST /api/appointments.

 THE HARD PART / CONFIRMING


 Example race-safe booking route
 This is a practical route skeleton. It depends on an isOpenSlot() helper which checks local business hours,
 30-minute alignment, and future time. You implement that helper alongside your slot generation logic.


     routes/appointment.routes.js (core creation logic)


     import { Router } from 'express';
     import mongoose from 'mongoose';
     import Appointment from '../models/Appointment.js';
     import Service from '../models/Service.js';
     import { requireAuth } from '../middleware/auth.js';
     import { isOpenSlot } from '../utils/slots.js';

     const router = Router();
     router.post('/', requireAuth, async (req, res, next) => {
       try {
         const { serviceId, startAt } = req.body;
         if (!mongoose.isValidObjectId(serviceId) ||
             typeof startAt !== 'string' || !startAt.endsWith('Z')) {
           return res.status(400).json({ message: 'Invalid input' });
         }

         const service = await Service.findOne({
           _id: serviceId, isActive: true
         });
         if (!service) return res.sendStatus(404);

         const starts = new Date(startAt);
         if (Number.isNaN(starts.getTime()) ||
             !(await isOpenSlot(starts))) {
           return res.status(400).json({ message: 'Invalid slot' });
         }

         const booking = await Appointment.create({
           customer: req.user.id, service: service._id,
           startAt: starts,
           endAt: new Date(starts.getTime() + 30 * 60 * 1000),
           status: 'confirmed', blocksSlot: true
         });
         return res.status(201).json({ id: booking.id, status: booking.status });
       } catch (err) {
         if (err.code === 11000) {
           return res.status(409).json({ message: 'That slot was just booked' });
         }
         next(err);
       }
     });
     export default router;




 Four things to verify
 •    Only a signed-in user reaches this route; req.user.id comes from your auth middleware.
 •    isOpenSlot() rejects anything outside business hours, in the past, or off the :00/:30 grid.
 •    The unique index has been created in MongoDB before booking tests run.
 •    The client never sends customerId, status, blocksSlot, or endAt as trusted values.
